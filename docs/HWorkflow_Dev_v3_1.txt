Core rules:
- Use workbook + GitHub + markdown operational memory as persistent project memory.
- Before implementation inspect ACTIVE_CONTEXT, AI_SESSION_HANDOFF,
  PROJECT_STATUS, CODEX_RULES, AI_ROUTING_RULES, CODEX_LIMIT_STATUS, and the
  workbook current milestone.
- Continue only from the next incomplete milestone.
- Start with the cheapest capable model: Gemini/Gemma -> DeepSeek -> Kimi -> Codex.
- Codex is a premium validation and execution engine, not the default
  implementation model.
- Reserve Codex for difficult debugging, repo-wide validation, build/test
  execution, dependency-aware debugging, difficult multi-file fixes, final
  milestone integration, and terminal-aware validation.
- Do not use Codex for simple docs, workbook-only updates, markdown-only updates,
  simple snippets, repetitive edits, simple UI tweaks, boilerplate, or basic
  refactoring unless explicitly requested.
- If Codex limits are moderate, use conservation mode: Kimi is primary
  implementation model, DeepSeek handles cheap/repetitive coding, Codex handles
  difficult validation only.
- If Codex limits are low, use emergency mode: stop normal Codex usage and
  reserve Codex for blockers only.
- If Codex is exhausted, continue in Roo Code with Kimi primary, DeepSeek backup,
  local machine builds/tests, GitHub, workbook, and markdown memory.
